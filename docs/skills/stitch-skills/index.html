從介面設計，走向可實作的畫面

用設計、建置與輔助技能，把 Google Stitch 接進 agent 的工作方式。

Stitch Skills 的重點是讓 agent 會使用 Google Stitch，並把設計與建置步驟接起來。它依工作分成設計、建置及輔助工具幾組。

它怎麼幫忙

使用前必須先設定 Stitch MCP 與需要的認證。有些技能彼此有相依關係，挑選安裝時要連同所需的技能一起準備。

可以這樣開口

這是一個可依需求修改的委託範例。

用 Stitch 為工作室預約服務探索手機畫面，先整理視覺系統，再依選定的方向做主要流程與可重複使用元件。

適合什麼工作

適合已使用 Stitch，想把介面探索與後續建置銜接的人。

開始之前

準備工具
設定完成的 Stitch MCP、相關認證，以及相容的 agent。
使用成本
依 Stitch、agent 及相關服務當前方案計算。

最近的觀察

2026-11-23：修正三項轉碼檢查：React 的條件 className 也會檢查寫死色碼；React Native 會攔下更多不能直接使用的 HTML／SVG 標籤；shadcn 可辨認 Tailwind v4 的 CSS-first 設定。例如把設計稿交給助手做手機介面時，較早發現誤用網頁標籤。仍需 Stitch／相應助手、Node 與專案依賴，這是檢查可靠性改進，沒有新增生圖功能。 2026-11-24：修正 React 頁面抽成單一 HTML 時的文字、引號與網址轉義，並保留 opacity、zIndex 等不帶 px 的樣式。例如交付作品集網頁時，標題中的 & 與透明度較不易變樣。仍需原本 Node／Stitch 與助手環境，沒有新增生成費。 2026-11-25：extract-design-md 現在可直接讀取公開網站網址，用本機 Chrome 擷取實際配色、字體、間距與畫面，整理成 DESIGN.md。例如整理客戶舊官網的設計規範，交給新版頁面沿用。這條路需 Node、Puppeteer／Chromium，不需 Firecrawl 或擷取 API key；只看見單頁當下狀態，未觀察的斷點與錯誤狀態須標未知。
